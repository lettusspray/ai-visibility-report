# Mercercroft — AI Visibility Snapshot

TanStack Start + Vite + React 19 SaaS that measures how a brand is recommended by AI
assistants (ChatGPT, Gemini, Perplexity, DeepSeek) and generates a PDF report per snapshot.

## Do not trust the README

`README.md` describes an obsolete Stripe one-time-purchase flow. The real app is
account-based: Supabase auth, Paystack subscriptions, plans (free/starter/pro defined
in `src/lib/types.ts` `PLANS`), brands → tracked_queries → snapshots. `orders` no
longer exists (dropped by `supabase/migrations/20260816091756_*.sql`).

## Commands

- `npm run dev` — dev server (note: lockfile is `bun.lock`; bun is not installed here)
- `npm run build` / `npm run build:dev` / `npm run preview`
- `npm run lint` — `eslint .` (verification; no test suite exists)

## Architecture

- File-based routing in `src/routes/`; conventions in `src/routes/README.md`.
  `src/routeTree.gen.ts` is generated — never edit.
- Server-side logic lives in `*.server.ts` modules (`src/lib/*.server.ts`) and
  `*.functions.ts` (server fns). `src/server.ts` is the SSR error wrapper and is
  wired as the Nitro entry in `vite.config.ts` — don't change that wiring.
- `src/start.ts` exists deliberately: defining it opts out of TanStack's
  auto-installed CSRF middleware, so CSRF is re-added explicitly. Don't delete it.
- `vite.config.ts` uses standard plugins: `tanstackStart()` from
  `@tanstack/react-start/plugin/vite`, `nitro({ preset: "cloudflare-module" })`,
  `tailwindcss()`, `tsconfigPaths()`, `react()`.

## Generated files — do not edit

`src/integrations/supabase/` `types.ts` (DB types) is auto-generated by Supabase
and must never be edited by hand. The other files in that directory (`client.ts`,
`client.server.ts`, `auth-middleware.ts`, `auth-attacher.ts`) are hand-written and
safe to modify.

`src/routeTree.gen.ts` is generated — never edit.

## Server/client module rules

- `supabaseAdmin` (service role, bypasses RLS) must be imported lazily inside
  handlers: `const { supabaseAdmin } = await import("@/integrations/supabase/client.server")`.
  Top-level import is only safe inside `.server.ts` modules — route and
  `*.functions.ts` files ship to the client bundle.
- User-scoped Supabase calls go through `requireSupabaseAuth` middleware, which
  injects `supabase`, `userId`, `claims` into the server-fn context.
- `server-only` package is banned by eslint; name modules `*.server.ts` instead.
- Secrets live in Vercel / Cloudflare (env vars at runtime): `SUPABASE_URL`,
  `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_PUBLISHABLE_KEY`,
  `BROWSER_USE_API_KEYS` (comma-separated pool), `BROWSER_USE_MODEL` (default
  `gpt-5.6-luna`), `BROWSER_USE_PROXY_COUNTRY`,
  `DEEPSEEK_API_KEY` (analysis LLM — required), `PAYSTACK_SECRET_KEY`,
  `PAYSTACK_PLAN_STARTER`, `PAYSTACK_PLAN_PRO`, `ADMIN_PASSWORD`.
  `.env` only holds publishable Supabase keys (`VITE_SUPABASE_URL`,
  `VITE_SUPABASE_PUBLISHABLE_KEY`).

## Report pipeline (src/lib/snapshot.server.ts)

`startSnapshot` (app.functions.ts) inserts a `snapshots` row then fire-and-forgets
`runSnapshot` via `void`. Pipeline: generate buyer questions → ask each engine →
computeStats (mention/citation %, product map, keyword visibility, sentiment) →
two-pass analysis (grounded draft with `[n]` footnotes, then an edit pass that
strips AI-writing tells and must preserve footnotes) → PDF via `pdf-lib` →
uploaded to Supabase storage bucket `reports` at `{user_id}/{snapshotId}.pdf`.
Clients poll via `refetchInterval`. A separate batched LLM pass
(`analyseSentiments`) tags every result positive/neutral/negative with a reason.

The dashboard is the report. The PDF is only an in-browser export (Download PDF
via `getSnapshot` signed url) or a shareable link (`/report/$token`). Nothing is
emailed unless the user opts in — there is no email infrastructure; don't add it.

## Brand brain + exploration

- New tables (migration `20260816100000_brand_brain.sql`): `brand_products`,
  `brand_facts` (kind fact|messaging), `brand_keywords`, plus
  `tracked_queries.keyword` (labels each custom/base question with the
  brand keyword it maps to). RLS is via subquery on `brands` (user_id =
  auth.uid()).
- `src/lib/loose-client.ts`: `asLoose(supabase)` casts the client so tables not
  yet present in the auto-generated DB types (see below) are queryable. Type-only
  helper — use it for `brand_products`/`brand_facts`/`brand_keywords` and any
  select/insert that touches `tracked_queries.keyword`. Never edit generated
  `src/integrations/supabase/types.ts` to add these.
- Server fns in `app.functions.ts`: `getBrandBrain`, `saveBrandProducts`
  (delete+insert), `saveBrandFacts`, `saveBrandKeywords`, and `getSnapshotAnswers`
  (`{results, previous}` = selected snapshot + prior complete one, for the
  compare view).
- Dashboard tabs: Current/Forecast/Fog of war + **Brain** (products, keywords,
  facts — the snapshot pipeline reads these as context and to compute the
  product map / keyword visibility / sentiment sections) and **Explore** (filter
  answers by platform/region/keyword/sentiment + text, compare to previous
  snapshot, CSV export). PDF has matching sections (03 product map & keywords,
  04 "How assistants talk about you" sentiment).

## Collection: Browser Use hosted agents (no AI provider APIs)

All answer collection runs through Browser Use Cloud hosted agents, so answers
match what a person sees in each web UI. Provider APIs are intentionally not
used. Vocabulary: browser-based monitoring / web-UI collection — never "scraping".

- `src/lib/key-pool.server.ts`: round-robin pool over `BROWSER_USE_API_KEYS`
  (also accepts `BROWSER_USE_API_KEY`), evicts keys for 60s after 2 consecutive
  failures (401/402/429), recovers on success.
- `src/lib/browser-use.server.ts`: `submitAgentTask` (V4 runs: POST `/runs`,
  poll `/runs/{id}/status`, fetch `/runs/{id}`; base `https://api.browser-use.com/api/v4`,
  auth header `X-Browser-Use-API-Key`). No profile IDs — every task opens a
  fresh browser session. If an engine rate-limits, the retry mechanism rotates
  to the next pool key.
- `src/lib/ai.server.ts`: `callAI` for generation/analysis always uses
  `DEEPSEEK_API_KEY` (`deepseek-v4-flash`, thinking disabled). The
  `ENGINES` registry drives browsers: `browser-perplexity` + `browser-chatgpt`
  work logged-out (no saved profile needed); `browser-deepseek` works logged-out;
  `browser-gemini`/`browser-claude`/`browser-metai`/`browser-grok` need a saved
  profile id in `BROWSER_USE_PROFILE_*` (M2). Engines without credentials are
  skipped, not errors. Concurrency is capped at 3 runs; retries rotate to the
  next pool key.
- Free tier: 5 questions per snapshot, 1 snapshot/month. Cache answers in the
  `raw_results` column; a new engine = a new `SITES` entry.

## Payment & admin

- Billing is Paystack (not Stripe). Webhook is `src/routes/api/public/paystack-webhook.ts`
  (HMAC SHA-512 verification). `/billing/callback` verifies the transaction.
- `/admin` is gated by the `ADMIN_PASSWORD` secret and offers snapshot regeneration.
- Public shared reports live at `/report/$token` keyed by the snapshot's
  `access_token` uuid; `getSharedSnapshot` is the only unauthenticated server fn.

## Deployment

- Build target: Cloudflare Workers via Nitro (`preset: "cloudflare-module"`).
- Deploy: `npm run build && npx wrangler deploy` (or via Cloudflare CI).
- Env vars are set in the Cloudflare dashboard (or `.dev.vars` for local dev).
- No Lovable dependency — all plugins are standard Vite/TanStack/Nitro.
